# 修改核对清单

## 修改前

- [ ] 阅读 `docs/README.md` 和本次涉及的 UI/animation/architecture 文档。
- [ ] 运行 `git status`，区分已有用户改动与本次改动。
- [ ] 如果涉及首页，逐项打开 `animation/inventory.md`，记录可能受影响的效果。
- [ ] 如果涉及字号或字体，同时检查中英文、桌面和移动四种组合。
- [ ] 如果涉及目录或依赖，确认业务应用与公共包的依赖方向未反转。

## 修改后

- [ ] 新增/删除/改变功能、动画、参数、断点、字号、颜色、目录或命令时已同步更新 `docs/`。
- [ ] Hero 入场在字体可见后才启动，英文和中文刷新时都可见，语言切换可重播副标题。
- [ ] Hero 漂浮圆点、About 逐字显色、章节翻字、标题 wave、产品视差、指针反馈和 Article 显现都仍存在。
- [ ] 标题 wave 作用于 shell 而非 `h1`/`h2` 文字本身，桌面峰值约 4°，移动端关闭。
- [ ] 英文快速上下滚动无明显字形跳动，松手尾段连续。
- [ ] About 未恢复英文 glyph 全量逐帧扫描，pointer reset 未在每帧重复创建 tween，Article 未在每滚动帧读取矩形。
- [ ] 中文字体为 Noto Sans SC，正文 500、UI/标题 700，未被整体缩小。
- [ ] 移动端使用原生滚动，正文没有水平溢出，按钮可点击。
- [ ] `.next`、`out`、日志、临时脚本、截图和性能采样没有进入 Git。
- [ ] `npm run lint`、`npm run build`、`npm run test:rendered` 均通过。

## 文档更新判定

“只是重构”也可能需要更新文档。只要文件位置、所有权、数据通道或运行顺序发生变化，就必须更新 architecture；只要用户能看到或感觉到变化，就必须更新 UI/animation；只要测试命令或验收方式变化，就必须更新 quality。
